# cartelera

Cineteca Nacional's showtimes (México, Chapultepec, Las Artes), scraped into
one static page: day agenda grouped by sede, posters, one-click tickets. No
backend, no build step. Updates twice a day via GitHub Actions.

Live at [cartelera.heliouz.com](https://cartelera.heliouz.com).

## Structure

```
scraper/        Python scraper (requests + BeautifulSoup)
scraper/letterboxd.py          film -> Letterboxd rating matching
scraper/previews.py            one link-preview page per film
docs/           static site (GitHub Pages root)
docs/data/      schedule.json, generated by the scraper
docs/p/         per-film link-preview pages (generated) + redirect.js
docs/og.png     link-preview image for the rest of the site
.github/workflows/scrape.yml   cron 2x/day + workflow_dispatch
```

## Scraper

```bash
cd scraper
pip install -r requirements.txt
python scrape.py
```

Writes `docs/data/schedule.json`. Aborts (exit 1, no write) if more than 20%
of detail-page fetches fail, or if the parsed film count drops below 50% of
the previous run — see `scrape.py` for the safeguards.

Each showtime carries `buy_url`, a direct link to that screening's checkout
page, read straight off the ticket anchor it was parsed from.

Films also carry `letterboxd` — a link and a 0-5 average — where one can be
matched confidently against Cineteca's own title, year, director and runtime.
Films that can't be matched, and shorts programmes that have no single entry,
simply carry `null` and render no badge. Letterboxd is never allowed to fail a
scrape; see `letterboxd.py`.

Before writing `schedule.json` it writes `docs/p/<id>/index.html` for every
film: a page whose `og:` tags carry the film's title and poster, so a shared
link previews as that film in WhatsApp and the like. People are sent on to
`/?film=<id>` by `docs/p/redirect.js`, which leaves link previewers on the
page. Each film that got a page is marked with `preview` in `schedule.json`,
and that is what the share button links to. Like Letterboxd, previews are
never allowed to fail a scrape.

To see a template change locally, run `python previews.py` from `scraper/`.
It rewrites the pages only and never touches `schedule.json`. Don't commit
its output: the next scheduled scrape rewrites every page whose content
changed.

### Tests

```bash
cd scraper
pip install pytest
python -m pytest -v
```

Runs offline against fixtures in `scraper/fixtures/`. No network requests.

## Frontend

No build step. To test locally:

```bash
cd docs
python -m http.server 8000
```

All filtering (day, sede, ciclo, search) happens client-side against the
already-fetched JSON.

## Deploy

GitHub Pages, deployed from `main` / `/docs`. The scrape workflow commits
`schedule.json` (and the preview pages) only when it changes — that commit is the deploy, no build
step. It opens a `scrape-failure` issue if a run fails.

Custom domain `cartelera.heliouz.com` is set via `docs/CNAME` and GitHub
Pages settings; DNS is a CNAME record at the registrar pointing to
`heliouz.github.io`.

## Not official

Not operated by Cineteca Nacional. Ticket purchases happen on the official
system (`cinetecanacional.net`); this project only aggregates and presents
the public schedule.
